# Agent 模式弹窗整理

新建任务页上，输入框上方那颗模式按钮（`PTC 模式 ⌄`）点开后的弹窗由官方
`dsh-client-ui-agent-preset` 提供，定位走 CSS 锚点定位，规则只保证「不溢出窗口」。
后果是：菜单很高时它照常向下展开、压在输入框卡片上；每一行又是「名称 + 描述」
两行文字塞进单行菜单项，勾选图标按单行居中，看起来挤且不齐。

本插件从外面把它扶正，不替换官方组件。

## 它做了什么

| 项 | 行为 |
| --- | --- |
| 方向 | 默认向下展开；只有下方挤不出 `minSpace`、且上方确实更宽裕时才改为上浮 |
| 位置 | 左边缘对齐按钮，横向越界时向左收 |
| 高度 | 封在按钮下方的可用空间上，底边停在距窗口下沿 `bottomInset` 的位置收口；内容更多就在列表内滚动 |
| 排版 | 行内改为顶部对齐，名称 13/18 半粗、描述 12/17 次级色，勾选靠右上角并对齐名称 |
| 圆角 | 面板与行的圆角各自比官方档位大 4px（`calc(var(--dsw-radius-lg) + 4px)` / `+4px`），看着更软 |
| 底色 | 不碰：面板表面、阴影、描边全部沿用官方菜单样式 |
| 主题 | 只用主题 token，明暗主题一起生效 |

窗口滚动、缩放（含桌面端祖先节点上的 CSS `zoom`）时会重新测量并重算位置。

## 可调参数

插件目录下的 `preset-menu.json`：

| 字段 | 含义 | 默认 | 范围 |
| --- | --- | --- | --- |
| `bottomInset` | 面板底边距窗口下沿的像素，越小面板向下伸得越低 | 12 | 0–200 |
| `sideGap` | 面板与模式按钮之间的间距 | 8 | 0–64 |
| `panelWidth` | 面板宽度 | 368 | 220–900 |
| `minSpace` | 下方不足这个高度就改为上浮 | 96 | 0–800 |

宿主半区每次请求 `/dsh-preset-menu/config` 都重读该文件，所以改完保存即可，**
下次点开菜单生效**，不用重启也不用刷新页面。文件缺失或写错时退回默认值，
越界数字会被夹回允许范围。

## 怎么识别

只看结构，不看哈希类名：`role="menu"` 的面板里只要有至少两行是「名称 + 描述」的
两段 `span` 结构，就认定是模式菜单。结构对不上——比如官方改了实现，或菜单里只有
一个选项——插件什么都不做，行为与安装前一致。

## 已知边界

- 只在新建任务页生效（会话开始后模式按钮是只读标签，没有弹窗）。
- 下方可用空间小于 `minSpace`、且上方也不比下方宽裕时，定位交还给官方样式表，只保留排版调整。
- 列表不显示滚动条，滚动位置没有额外提示——靠滚轮 / 触控板 / 方向键继续翻。
- 不注册工具、不写配置；除了读取自己的 `preset-menu.json`，不发任何网络请求；卸载后弹窗立即回到原样。
